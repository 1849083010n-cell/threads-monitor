## 一、数据存储：就是 SQLite，一个文件

Demo 阶段所有数据都在项目根目录的 `tokens.db` 一个文件里：

| 数据 | 存哪 | 说明 |
|------|------|------|
| OAuth Token | tokens.db 的 token 表 | 授权时自动写入 |
| 搜索结果 | 内存（实时展示） | Demo 不落库，重启即清 |

什么都不用装、不用配。生产版再考虑 PostgreSQL，现在不需要。

## 二、你要做的只有 5 步

### 第 1 步：Meta 后台创建应用（10 分钟，手动）

1. 打开 https://developers.facebook.com/apps/ 登录
2. 创建新应用，Use Case 选 **"Access the Threads API"**
3. 进入 Use Cases → Access the Threads API → Customize，记录：
   - **Threads App ID**（THREADS_ 开头）
   - **Threads App Secret**（THREADS_ 开头）
4. 同一页 Redirect Callback URLs 添加：**http://localhost:5001/callback**
5. App Roles → Roles → Add People → 选 Threads Tester → 输入你的 Threads 用户名
6. 手机/网页打开 Threads → 设置 → 网站权限 → 邀请 → **接受邀请**（这步漏了必失败）

### 第 2 步：填 .env（30 秒）

编辑 `/Users/erzhuonie/Desktop/印尼舆情管理/threads-舆情监控/.env`：

```
THREADS_APP_ID=第1步拿到的ID
THREADS_APP_SECRET=第1步拿到的Secret
THREADS_REDIRECT_URI=http://localhost:5001/callback
```

### 第 3 步：重启服务（10 秒）

```bash
cd ~/Desktop/印尼舆情管理/threads-舆情监控
source venv/bin/activate
python app.py
```

看到 `🚀 Threads 舆情监控 Demo 已启动` 且没有 ⚠️ 提示 = 成功。

### 第 4 步：浏览器授权（1 分钟）

打开 http://localhost:5001 → 点「🔑 授权 Threads 账号」→ Meta 页面登录你的测试账号 → 同意权限 → 跳回页面显示「✅ 已授权」

### 第 5 步：搜索验证（10 秒）

输入英文关键词（如 Chery）→ 点「🔎 搜索」→ 看到帖子列表 + 情感标签（正面 😊 / 负面 😞 / 中性 😐）

## 三、Meta 后台需要开通的服务/权限

### 3.1 需要开通的权限（App Dashboard → App Review → Permissions and Features）

| 权限 | 必需 | 用途 | 后台状态 |
|------|------|------|----------|
| threads_basic | ✅ | 读取账号基本信息 | 默认就有，无需申请 |
| threads_keyword_search | ✅ 核心 | 关键词搜索帖子 | **需要提交 App Review 申请**（见下） |
| threads_read_replies | 可选 | 读帖子回复 | Tester 角色默认可用 |

**threads_keyword_search 的坑（重要）：**
- 它不在 OAuth 授权窗口的 scope 列表里（官方 scope 只有 threads_basic / threads_content_publish / threads_read_replies / threads_manage_replies / threads_manage_insights）
- 它是在 **App Review → Permissions and Features** 里单独申请的权限
- **未获批时：关键词搜索只能搜到「已验证身份用户」（即 Tester 自己）发的帖子**
- 获批后：才能搜索全站公开帖子（审批需要时间，Demo 阶段可先不提交）

**Demo 阶段的应对**：先用你的测试账号发 2-3 条含关键词的帖子（如 "I love Chery car"、"Chery is terrible"），未获批也能搜到自己的帖子，流程照样能验证。

### 3.2 明确不需要开通的服务

以下全部**不用**开，不要点：
- ❌ Facebook Login
- ❌ Instagram API（Instagram 基础展示/内容发布）
- ❌ Messenger / WhatsApp
- ❌ Graph API 其他用例

只需一个：**"Access the Threads API" Use Case**（创建应用时选它，应用面板里会自带 Threads 相关配置项）。

### 3.3 OAuth 授权窗口实际请求的权限（代码已按官方修正）

```
scope=threads_basic,threads_read_replies
```
（threads_keyword_search 不放在这里，放这里会报错或无效）

### 3.4 应用面板其他必配项

| # | 配置项 | 值 |
|---|--------|-----|
| 1 | Threads App ID / Secret | THREADS_ 开头（Use Cases → Access the Threads API → Customize 里看） |
| 2 | 有效 OAuth URI / Redirect Callback URLs | http://localhost:5001/callback |
| 3 | App Roles → Threads Tester | 添加你的测试账号 |
| 4 | 测试账号接受邀请 | Threads 设置 → 网站权限 → 邀请 → 接受（漏了必失败） |

## 四、想让手机/别人也能访问？（可选，一条命令）

本地跑通后，如果想让手机测试或给别人演示，用 ngrok 免费隧道：

```bash
# 新开一个终端窗口
ngrok http 5001
```

会输出一个 https 公网地址，如 `https://snub-cataract-launder.ngrok-free.dev`

用法：
- 手机浏览器直接打开该地址即可访问（首次会有一个 ngrok 中间提示页，点 Visit Site）
- 如果想在公网地址上走 Meta 授权：把 Meta 后台回调 URL 临时改成 `https://你的ngrok地址/callback`，同时改 .env 的 THREADS_REDIRECT_URI，重启后重新授权

⚠️ 免费版 ngrok 每次启动地址都会变，所以每次重启隧道后，Meta 回调也要跟着改。这是免费方案的唯一麻烦，纯本地测试完全不受影响。
